The fault: in /home/matt/Git/Trexy/crates/vectrex/src/memory.rs, Memory::tick currently does `let driven = self.psg.cycle(pins.b, pins.a).unwrap_or(IDLE_BUS); self.via.set_pins_a(driven);` — when the PSG is not driving the bus, pins_a is forced to 0xFF on ALL bits, including the bits the VIA itself is driving as outputs (DDRA=0xFF while the DAC is being run). Since Via::read(ORA) returns the pin level (pins_a), any read-modify-write of $D001 by the BIOS (e.g. NEG <$01 at $F4D3 in the print routine, which negates the X sweep rate for the return sweep) reads 0xFF instead of the driven DAC code, so the beam never sweeps back left between text raster rows and the text smears rightward across the screen.

Work test-first: in the existing `mod tests` of memory.rs add a unit test, e.g. `a_driven_port_a_bit_reads_back_what_the_via_drives`: build `Memory::new(vec![0; 0x2000], Vec::new())`, write 0xFF to $D003 (DDRA), write 0x60 to $D001 (ORA), then assert `mem.read(0xD001) == 0x60` — with a comment noting the BIOS's NEG <$01 return-sweep depends on this. Also assert the input case still floats high: on a fresh Memory (DDRA=0), after one `mem.internal()`, `mem.read(0xD001) == 0xFF`. Run `cargo test --workspace` and confirm the new driven-bit assertion FAILS (returns 0xFF) before fixing.

Then the fix, in Memory::tick only: when the PSG is not driving, the bus level is the VIA's own output on output bits and the floating idle level on input bits. Replace the unwrap_or(IDLE_BUS) arm with `pins.a & self.via.ddra | IDLE_BUS & !self.via.ddra` (pins.a here is via.pins().a, i.e. ora & ddra on output bits). Update the adjacent comment to describe the new behaviour (per user CLAUDE.md: describe how it is now). Keep the Some(psg_value) arm exactly as it is (the PSG drives the whole bus when reading — the BIOS only does that with DDRA=0x00).

Do not touch crates/beam-rasteriser, crates/tube-renderer, crates/tube-shell, crates/m6809, Constants::vectrex(), fixtures/, or profiles/. Do not commit.
