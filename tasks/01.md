Confirm, on this machine, the already-diagnosed layer-1 fault that makes BIOS text enormous. Background: the Vectrex BIOS print routine (in the 8K image at ~/.cache/trexy/roms/'Mine Storm (1982).vec', which contains the BIOS) draws each text raster row as ONE ramp: it writes 0x60 to the DAC ($D001, X rate +0.75), asserts ~RAMP by writing 0x01 to ORB ($D000), feeds the shift register ($D00A) one glyph byte every 18 cycles (7 characters), then ends the sweep with ORB=0x81 after 144 cycles. Then, at PC $F4D3, it executes NEG <$01 (ROM bytes 00 01 at file offset 0x14D3 — confirm with: xxd -s $((0x14D3)) -l 2 "$HOME/.cache/trexy/roms/Mine Storm (1982).vec") — a read-modify-write on VIA port A meant to negate the driven DAC code (0x60 -> 0xA0 = rate −0.75) so the beam sweeps back LEFT before the next row. In the emulation, Via::read(ORA) returns pins_a, and Memory::tick (crates/vectrex/src/memory.rs) sets pins_a every cycle to psg.cycle(...).unwrap_or(IDLE_BUS=0xFF) — so with DDRA=0xFF and the PSG inactive the read returns 0xFF, NEG writes 0x01, and the 'return' sweep drifts +0.008 RIGHT for 144 cycles. Every text row therefore starts about one row-width further right; the text block smears across the screen, which is the oversized-text symptom, the +X DC bias, and the inverted (landscape) x/y extent ratio.
